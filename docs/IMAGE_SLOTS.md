## Pixel sizes (2× rule)

Needed width = displayed CSS width × 2, capped at 2000 px (the processing script makes 480 / 800 / 1200 / 1600 / 2000). Full-screen slots show 1440 × 900 on desktop → source at least 2000 px wide (2400 recommended); product slots show 448 px cards and a 676 px gallery but the gallery grows to ~1150 px on tablets → source at least 1600 px wide, 2000 px for the main shot.

## Rules for the next step (9B-2)

1. **Sources.** Only Unsplash, Pexels or Pixabay. Open every photo's own page and read its licence text (do not assume). Skip anything with a visible brand logo, an identifiable recognizable person unless the licence clearly allows commercial use for that use, trademarked items or designs, and "Unsplash+" / premium-only content.
2. **Faces.** Prefer hands, wrists, necklines and product-only shots; no slot needs an identifiable face.
3. **`images.json`.** One entry per image: slot id, source site, photo page URL, author name and profile URL, licence name + licence page URL, date checked, final filenames. A script generates `CREDITS.md` from it (credit text even where attribution is not required).
4. **Processing script** `scripts/build-images.mjs`: reads `assets-incoming/`, writes WebP (JPEG fallback only if needed) at 480 / 800 / 1200 / 1600 / 2000 px wide (only up to the source width), plus `srcset` / `sizes` metadata the `Image` component can use, a tiny blur or dominant-colour placeholder and a total image-weight report per route. `sharp` stays out of the shipped dependencies (devDependency or run through `npx`); the processed files are committed so a buyer needs no tooling.
5. **Home video.** A Pexels or Pixabay video whose licence allows redistribution inside a template (read the exact terms; if it only allows use, not redistribution of the file, host nothing and fall back). Re-encode to ≤ 2.5 MB, muted, looping, with a poster; no autoplay under `prefers-reduced-motion` or data-saver. If nothing suitable exists, use the still with a gentle CSS motion instead.
6. **No layout movement:** keep the aspect ratios in the table; run the page-height comparison (DESIGN_NOTES §28 method) after wiring.
